# Авторизация и роли

## Стартовые аккаунты

При startup сервис создаёт отсутствующие аккаунты `admin`, `user1` и `user2`. Логины,
email и стартовые пароли задаются секцией `[auth]` или переменными
`BOND_TRADING__AUTH__BOOTSTRAP_*`. В Docker Compose удобные короткие переменные из
`.env` преобразуются в эти настройки.

Bootstrap не перезаписывает существующего пользователя или его изменённый пароль.
Пароли должны содержать не меньше 12 символов и хранятся как Argon2 hash. Значения
`change-me-*` допустимы только на локальной машине.

## Web-сессия

После входа backend создаёт криптографически случайный session token. В PostgreSQL
хранится только его SHA-256 hash. Браузер получает:

- HttpOnly cookie с session token;
- отдельный CSRF cookie;
- срок действия, по умолчанию 7 дней.

Все изменяющие запросы из cookie-сессии требуют тот же CSRF в form field или
`X-CSRF-Token`. Cookies имеют `SameSite=Lax`; для HTTPS deployment нужно включить
`auth.secure_cookies=true`.

Logout отзывает текущую серверную сессию. Смена пароля и блокировка пользователя
отзывают все его активные сессии.

## Программный клиент

Login возвращает `access_token` и `csrf_token`:

```bash
curl -sS http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"login":"user1","password":"YOUR_PASSWORD"}'
```

Для CLI/интеграции передавайте `access_token` как Bearer. Bearer-запрос не использует
cookie и поэтому не требует CSRF:

```bash
curl -sS http://127.0.0.1:8000/api/v1/lots \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN'
```

Токен нужно хранить как пароль: endpoint login показывает его только при создании
сессии, восстановить его из БД невозможно.

## Права

Роль `user` управляет только своими лотами, настройками, импортами и файлами. Роль
`admin` дополнительно:

- просматривает всех пользователей;
- создаёт пользователя с ролью `user` или `admin`;
- блокирует и разблокирует аккаунты;
- видит общий журнал загрузок;
- может скачать оригинал загрузки для расследования ошибки.

Последнего активного администратора отключить нельзя. Общий справочник облигаций и
снимки MOEX разделяются между пользователями, но финансовые позиции не разделяются.

## Что ещё нужно перед публичным production

- TLS и `secure_cookies=true`;
- уникальные секреты вне Git;
- rate limiting и журнал неуспешных попыток login;
- MFA/SSO, если сервис будет доступен из Интернета;
- recovery-процесс и ротация администраторов;
- регулярное удаление истёкших сессий и политика хранения файлов;
- независимый security review.

Конфигурация с `environment=production` не запустится с `change-me-*` secrets или
`secure_cookies=false`: это намеренная защита от случайной публикации локальных
значений.
