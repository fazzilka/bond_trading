# Автоматическое обновление Google Таблицы

Интеграция обновляет существующую таблицу заказчика на месте. Приложение читает ISIN
и исходные данные покупки, получает рыночные данные MOEX и записывает результат только
в назначенные и зарезервированные колонки. Пользовательские формулы в остальных
ячейках не перезаписываются.

## Что появляется в таблице

Для каждой непустой строки с корректным ISIN записываются:

- лучшее предложение `OFFER` в процентах или рублях за одну облигацию;
- текущий НКД;
- время котировки в часовом поясе приложения;
- количество купонов, выплаченных после приобретения;
- общую сумму полученных купонов по всей позиции;
- текущую стоимость позиции, доход до налога и чистый доход;
- текущую годовую доходность после налога и отклонение от плана;
- технический статус `FRESH`, `NO OFFER`, `ERROR` или `INVALID ISIN`.

Если один ISIN встречается несколько раз, цена обновляется во всех таких строках, а
MOEX запрашивается один раз за цикл. При отсутствии `OFFER` старая цена очищается:
цена последней сделки намеренно не подставляется вместо лучшего предложения. Строка с
некорректным ISIN получает статус, но её прежняя цена и соседние формулы не меняются.

## Профиль листа «Доход счёт 2026»

Исходные значения берутся из существующих колонок:

| Колонка | Значение | Правило |
|---|---|---|
| E | дата приобретения | вводится пользователем |
| H | количество | вводится пользователем |
| I | фактическая цена приобретения, ₽/шт. | вводится пользователем |
| J | НКД при приобретении, ₽/шт. | если пусто, фиксируется из MOEX History по дате E |
| L | общая комиссия покупки, ₽ | если пусто, один раз записывается `0.4` |
| V | плановая годовая доходность, % | используется для отклонения, необязательно |

Значение L — общая комиссия строки, поэтому оно не умножается на количество. Уже
заполненные значения J и L никогда не заменяются автоматически.

Расчётные колонки `AD:AL` зарезервированы приложением:

| Колонка | Результат |
|---|---|
| AD | текущий НКД MOEX за одну облигацию |
| AE | число состоявшихся купонных выплат |
| AF | полученные купоны по всей позиции |
| AG | текущая стоимость с купонами и НКД |
| AH | текущий доход до налога |
| AI | текущий чистый доход |
| AJ | текущая годовая доходность после налога |
| AK | отклонение от плана V, процентные пункты |
| AL | статус расчёта или причина отсутствия результата |

Число выплат определяется по реальным датам купонов: `дата приобретения < дата
купона ≤ дата котировки`. Поэтому покупка за два дня до купона корректно даёт одну
выплату после наступления даты купона.

## Подготовка Google Cloud

1. Создайте отдельный проект Google Cloud или выберите существующий.
2. Включите Google Sheets API.
3. Создайте service account только для Bond Trading.
4. Создайте для него JSON-ключ и сохраните локально как
   `secrets/google-service-account.json`.
5. Откройте нужную Google Таблицу и выдайте адресу service account роль редактора.

Каталог `secrets` исключён из Git. JSON-ключ нельзя отправлять в репозиторий, PR,
чат или хранить внутри Docker image. При утечке ключ нужно удалить в Google Cloud и
создать новый.

В `.env` включите интеграцию:

```dotenv
BOND_TRADING__GOOGLE_SHEETS__ENABLED=true
BOND_TRADING__GOOGLE_SHEETS__CREDENTIALS_FILE=/run/secrets/google-service-account.json
BOND_TRADING__GOOGLE_SHEETS__WORKER_POLL_SECONDS=5
BOND_TRADING__GOOGLE_SHEETS__DEFAULT_SYNC_INTERVAL_SECONDS=300
```

Для запуска без Docker путь должен быть локальным, например:

```dotenv
BOND_TRADING__GOOGLE_SHEETS__CREDENTIALS_FILE=secrets/google-service-account.json
```

После изменения `.env` пересоздайте backend и worker:

```bash
docker compose up --build -d backend sheet-sync-worker
docker compose logs -f sheet-sync-worker
```

## Настройка в приложении

Откройте `/integrations/google-sheets` и заполните:

- ссылку или ID таблицы;
- точное название вкладки, например `Доход счёт 2026`;
- номер строки заголовка;
- колонку ISIN;
- отдельные колонки цены, времени и статуса (для рабочего листа `AA`, `AB`, `AC`);
- режим цены и интервал обновления.

Колонки подключения не могут совпадать с исходными `E/H/I/J/L/V` и расчётными
`AD:AL`. Для согласованного сценария выберите «Лучшее предложение (OFFER), ₽ за
облигацию». Сначала сохраните настройки, затем нажмите «Проверить доступ». После
успешной проверки включите автоматическое обновление. Кнопка
«Обновить сейчас» ставит внеочередное задание в ту же надёжную очередь.

## MOEX ISS

Публичные данные MOEX ISS доступны без отдельного API-ключа. Поэтому для обычного
запуска поля `BOND_TRADING__MOEX__PASSPORT_LOGIN` и
`BOND_TRADING__MOEX__PASSPORT_PASSWORD` остаются пустыми, а
`BOND_TRADING__MOEX__REQUIRE_AUTH=false`. Passport нужен только при наличии
отдельной подписки MOEX, условия которой требуют авторизованный доступ.

Публичный источник может быть задержанным или неполным. Приложение сохраняет время
рынка и время получения, не объявляет данные realtime и не заменяет отсутствующий
`OFFER` последней сделкой.

## Очередь и автоматические события

Отдельный процесс `sheet-sync-worker`:

1. находит подключения, у которых наступил интервал обновления;
2. атомарно забирает одно задание из PostgreSQL;
3. читает ISIN и исходные значения покупки из строки;
4. обновляет уникальные бумаги через MOEX ISS;
5. отправляет в Google `values:batchUpdate` только для назначенных ячеек;
6. сохраняет число строк, ошибки и время результата в журнале.

Новое задание также создаётся после подтверждённого импорта, добавления, изменения
или удаления лота, изменения расчётных настроек и ручного обновления MOEX. Пока для
подключения уже есть задание в очереди, повторные события объединяются с ним. Событие,
пришедшее во время выполняющейся синхронизации, создаёт ровно один следующий запуск,
поэтому изменение не теряется. При временной ошибке worker делает до трёх попыток с
увеличивающейся паузой.

## Проверка без реальных API

Основной end-to-end тест использует память вместо Google и предсказуемые ответы
вместо MOEX. Он проверяет повторяющиеся ISIN, точные адреса обновляемых ячеек,
сохранность формул, отсутствие `OFFER`, исторический НКД, выплаченные купоны,
комиссию из L, некорректный ISIN, расписание, дедупликацию заданий, повторные попытки
и разделение пользователей:

```bash
uv run pytest -q tests/integration/test_google_sheets_sync.py tests/unit/google_sheets
```

Реальная сквозная проверка становится возможной только после выдачи service account
доступа к тестовой Google Таблице. Её следует проводить сначала на копии таблицы.

## Диагностика

- `Не найден JSON-ключ` — неверен путь или файл не смонтирован в контейнер.
- `проверьте service account и права Editor` — таблица не расшарена на адрес service
  account либо ключ от другой учётной записи.
- `Вкладка … не найдена` — название вкладки не совпадает посимвольно.
- `NO OFFER` — MOEX не вернул лучшее предложение; это не ошибка Google.
- `INVALID ISIN` — значение в строке не прошло проверку формата и контрольной цифры.

История последних заданий доступна на странице интеграции и через API. Метрики
worker публикуются в Prometheus как `bond_trading_sheet_sync_*`.
